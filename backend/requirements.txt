#
# 【PDF 导出方案说明 —— 决策记录，勿改回 WeasyPrint】
#   本工程的 PDF 报告导出**统一使用 PyMuPDF（见第六节 pymupdf==1.25.1）**，
#   通过 fitz 原生绘图 API 直接绘制 A4 版式，不依赖任何外部渲染引擎。
#
#   历史方案与废弃原因（2026-09-19 实测记录）：
#     曾尝试 weasyprint==70.0（HTML → PDF，排版能力好），但 WeasyPrint 的文本
#     排版层强依赖 GTK/Pango 系统库（libgobject-2.0-0 / libpango-1.0-0 等）。
#     在 Windows 上即使 pip 安装成功，运行期仍必然抛出：
#         OSError: cannot load library 'libgobject-2.0-0': error 0x7e
#     该问题的唯一解法是要求部署方额外安装 GTK3 运行时（MSYS2 / GTK-for-Windows），
#     违背本工程"零系统级依赖、Windows 原生开箱可运行"的部署约束，
#     故连同 md2pdf==1.5.0 / xhtml2pdf==0.2.16 一并移除。
#
#   若未来确需换回 HTML 排版引擎（例如要支持复杂 CSS 分页），
#   必须先确认目标部署环境已预装 GTK3 运行时，再恢复本节依赖，
#   同时修改 app/services/pdf_renderer.py 的渲染后端实现。

# 【必须锁定 4.0.1，不可升级】
#   bcrypt >= 4.1 移除了 passlib 1.7.4 依赖探测所需的 __about__ 属性，
#   bcrypt >= 5.0 进一步将"密码超过 72 字节"改为硬报错，
#   二者均会导致 passlib 的 CryptContext(schemes=["bcrypt"]) 在
#   首次 hash() 时抛出 AttributeError / ValueError，密码哈希功能彻底不可用。
#   4.0.1 是当前与 passlib 1.7.4 配合最稳定的版本，已经实测验证通过。
bcrypt==4.0.1
