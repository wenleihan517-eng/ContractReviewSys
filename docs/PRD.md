## 一、产品概述

### 1.1 产品定位

面向企业合同审批场景的**自动化合规审查系统**。系统在合同进入人工审批环节之前，
自动完成合同解析、条款结构化、合规风险审查、修改建议生成与审批回写，
把法务人员从"逐条通读合同找问题"的重复劳动中释放出来，
同时保证审查结论**可复现、可审计、可举证**。

### 1.2 要解决的核心问题

| 现状痛点 | 本系统对策 |
|---|---|
| 合同条款靠人工通读，漏检率高 | 34 条风险规则 + 多路召回，逐条确定性匹配 |
| 不同审查人对同一合同结论不一致 | 规则引擎确定性裁决，同一输入结论恒等 |
| 审查意见无法追溯"为什么定成高风险" | 每条风险项绑定规则编码与法条依据 |
| 大额/涉外合同风险敞口大 | 差异化路由，大额高风险合同走深度复核链路 |
| 扫描件、加密件卡在流程里无人处理 | 三类法定阻断码 + 人工重跑/驳回闭环 |
| 审查结论被质疑篡改 | 结论 SHA-256 哈希校验 |

### 1.3 产品边界（明确不做）

**仅围绕以下 8 项能力开发，不做范围外功能：**

1. 合同解析
2. OCR 识别
3. 条款结构化
4. 合规风险审查
5. 智能建议生成
6. 审批回写
7. 报告导出
8. 规则模板管理

**明确不做**：不替代审批系统本身（不做审批决策）、不做合同起草与生成、
不做电子签章、不做供应商管理、不做财务对账。

## 二、核心业务红线（最高优先级需求）

> 本节是全系统**最高约束**。任何功能设计、任何技术选型，与本节冲突时以本节为准。

### 2.1 权责划分铁律

| 能力 | 承担方 | 是否可参与正式判定 |
|---|---|---|
| 条款语义解析 | 大模型（辅助） | ✗ |
| 疑似风险识别 | 大模型（辅助） | ✗ |
| 修改建议初稿 | 大模型（辅助） | ✗ |
| 合规条文解读 | 大模型（辅助） | ✗ |
| **风险等级定级** | **规则引擎** | ✓ 唯一 |
| **违规判定** | **规则引擎** | ✓ 唯一 |
| **任务阻塞判定** | **规则引擎** | ✓ 唯一 |
| **最终审查结论** | **规则引擎** | ✓ 唯一 |

**一句话表述**：大模型只负责"读懂和提议"，规则引擎负责"定性和定级"。
大模型无论输出什么内容，都不可能改变任何一个正式结论。

### 2.2 需求层面的验收判据

| # | 判据 | 验证方式 |
|---|---|---|
| R1 | 大模型的产出物在数据结构上**不存在**等级、判定、结论字段 | 检查 `LLMCandidate` / `VectorCandidate` 模型定义，确认无 `risk_level` / `severity` / `decision` 字段 |
| R2 | 任何写入风险等级的数据，其来源必须标记为规则引擎 | 检查 `RiskItem.judge_source` 的校验器，非 `rule_engine` 直接拒绝 |
| R3 | 审查结论的来源必须唯一为规则引擎 | 检查 `ReviewConclusion.decision_source` 只接受 `rule_engine` |
| R4 | 规则引擎关闭时必须拒绝放行，不得静默降级 | 关闭 `RULE_ENGINE_ENABLED` 后触发审查，应抛异常而非返回"无风险" |
| R5 | 法务人员补充意见不得改动任何判定字段 | 补充意见后重新校验结论哈希相关字段不变 |

## 三、用户角色与权限

### 3.1 角色定义

系统共 3 种角色，**无注册功能**，账号由管理员预置。

| 角色值 | 角色名称 | 定位 | 权限点数量 |
|---|---|---|---|
| `business_user` | 业务经办人 | 提交合同、跟踪进度、下载报告 | 3 |
| `law_user` | 法务审查人 | 审查风险、补充意见、触发回写 | 6 |
| `admin` | 系统管理员 | 规则维护、阻塞处理、系统监控 | 11 |

### 3.2 权限点全表（11 项）

| 权限值 | 名称 | 经办人 | 法务 | 管理员 |
|---|---|:---:|:---:|:---:|
| `contract:upload` | 上传合同 | ✓ | | ✓ |
| `task:view_own` | 查看自己提交的任务 | ✓ | ✓ | ✓ |
| `task:view_all` | 查看全部任务 | | ✓ | ✓ |
| `report:download` | 下载审查报告 | ✓ | ✓ | ✓ |
| `risk_item:edit` | 编辑风险项（批注/建议） | | ✓ | ✓ |
| `comment:annotate` | 人工批注 | | ✓ | ✓ |
| `approval:write_back` | 触发审批回写（仅评论通道） | | ✓ | ✓ |
| `rule_template:manage` | 维护合规规则模板 | | | ✓ |
| `user:manage` | 管理用户 | | | ✓ |
| `blocked_task:handle` | 处理阻塞任务 | | | ✓ |
| `system:monitor` | 系统监控 | | | ✓ |

### 3.3 权限矩阵的唯一权威源

**需求约束**：权限矩阵必须在一处定义，前后端引用同一份语义。
禁止前后端各写一套，禁止在业务代码里散落 `if role == 'admin'` 这类硬编码判断。

**验收判据**：修改任一角色的权限，只需改动权威源一处，前后端行为同步变化。

### 3.4 越权访问的处理要求

| 越权类型 | 要求 |
|---|---|
| 前端访问无权限页面 | 不得白屏或报错，应跳转到该角色首页并给出提示 |
| 后端调用无权限接口 | 必须返回明确的"无权限"错误码，不得返回数据 |
| 横向越权（访问他人任务） | 业务经办人只能看到自己创建的任务，查询强制追加归属过滤 |
| 纵向越权（低权限调高权限接口） | 一律拒绝 |
| 路径绕过（构造路径变体） | 一律拒绝，不得通过路径变形规避校验 |

## 四、功能需求

> 编号规则：`FR-模块-序号`。每条需求包含"需求描述 / 判定标准 / 优先级"。

### 4.1 合同接入与解析（FR-PARSE）

| 编号 | 需求 | 判定标准 | 优先级 |
|---|---|---|---|
| FR-PARSE-01 | 支持上传 PDF / DOCX / 图片格式合同 | 三类格式均可上传成功并返回对象键 | P0 |
| FR-PARSE-02 | 支持电子合同直接抽取文本 | 可选中文字、正常返回全文与分页文本 | P0 |
| FR-PARSE-03 | 支持扫描件走 OCR 识别 | 无文字层的图片 PDF 能识别出文本 | P0 |
| FR-PARSE-04 | 支持混合型文档（部分页有文字层、部分页需 OCR） | 同一份文件中两种来源均被正确抽取 | P1 |
| FR-PARSE-05 | 解析结果必须保留**字符级位置** | 每个文本块记录起止下标，可用于原文定位 | P0 |
| FR-PARSE-06 | 条款自动结构化并分类 | 按 14 类条款类型归类，含当事人信息、付款、交付、违约责任等 | P0 |
| FR-PARSE-07 | 条款分类要有标题优先规则 | 标题含"违约责任"的条款必须归为违约责任类，不因正文含"赔偿"而错分 | P0 |
| FR-PARSE-08 | 自动抽取合同元数据 | 抽取出合同类型、金额、相对方等，供路由决策使用 | P1 |

**位置坐标系要求**（关键需求，影响前端高亮）：

- 文本块位置与风险项位置使用**同一套坐标系**，区间为**左闭右开**
- 前端按风险区间切分原文后，**拼接结果必须严格等于原文**（零丢失、零重复）
- 重叠的风险区间必须合并后再切分
- 跨页风险需正确换算为页内偏移
- 无位置信息的风险项（起止均为 0）显示为「全文」，**禁止编造页码**

### 4.2 审查任务与差异化路由（FR-TASK）

| 编号 | 需求 | 判定标准 | 优先级 |
|---|---|---|---|
| FR-TASK-01 | 创建审查任务时自动做路由决策 | 返回明确的路由类型 | P0 |
| FR-TASK-02 | 三条路由链路 | 快速通道 / 标准审查 / 深度复核，判定逻辑确定 | P0 |
| FR-TASK-03 | 路由优先级明确 | 同时满足多条件时优先级为：深度复核 > 快速通道 > 标准审查 | P0 |
| FR-TASK-04 | 深度复核触发条件 | 金额达到阈值（默认 500 万）或属于高风险合同类型（涉外合作/股权转让/担保/借款） | P0 |
| FR-TASK-05 | 快速通道触发条件 | 模板合同，仅跑结构化规则 | P1 |

### 4.3 合规风险审查（FR-REVIEW）

| 编号 | 需求 | 判定标准 | 优先级 |
|---|---|---|---|
| FR-REVIEW-01 | 规则引擎确定性匹配 | 支持 7 种匹配方式（见 4.9） | P0 |
| FR-REVIEW-02 | 多路召回 | 规则命中 + 向量语义召回 + 大模型辅助，三路并行 | P0 |
| FR-REVIEW-03 | 风险等级四级 | 低 / 中 / 高 / 严重，数值越大风险越高 | P0 |
| FR-REVIEW-04 | 规则严重度到风险等级的映射确定 | 规则自身严重度（提示/轻微/重大/致命）经固定映射表得到风险等级 | P0 |
| FR-REVIEW-05 | **合同级规则不得重复计数** | 必备条款缺失、大额提示这类整份合同一条的规则，只产出 1 条风险项 | P0 |

| FR-REVIEW-10 | **人工编辑不得改变定级** | 编辑后风险等级、判定、结论保持不变 | P0 |
| FR-REVIEW-11 | 推荐条款可替换 | 法务可从条款库中选择更合适的示范条款 | P1 |
| FR-REVIEW-12 | 风险等级分布统计准确 | 各等级数量之和等于风险项总数 | P0 |

| FR-BLOCK-06 | 阻塞任务可恢复 | 人工处理后回到原阶段继续执行，不从头重跑 | P0 |

### 4.9 规则匹配能力（7 种，FR-MATCH）

| 匹配方式 | 说明 | 典型用途 |
|---|---|---|
| 关键词命中 | 文本包含指定关键词 | "签订后即支付全部"这类明示违规表述 |
| 正则命中 | 正则表达式匹配 | 复杂语序的侵权责任转嫁条款 |
| 条款类型命中 | 针对某类条款整体判定 | 付款条款必须含验收约定 |
| 语义相似度命中 | 向量相似度超过阈值 | 变体表述的同类风险 |
| 字段数值比较 | 比较合同字段数值 | 金额、期限等 |
| 必备条款缺失 | 应含某类条款而缺失 | 缺交付验收条款、缺质量保证条款 |
| 数值阈值校验 | 数值是否越界 | 违约金比例上限、付款周期上限 |

## 五、状态机需求

### 5.1 审查任务状态（8 态）

```
待执行 → 执行中 → 大模型完成 → 规则定级完成 → 审查完成
   ↓         ↓            ↓              ↓
   └─────────┴────────────┴──────────────┴──→ 失败
   └─────────┴────────────┴──────────────┴──→ 阻塞 → 人工处理 → 回到原阶段
                                            └→ 人工取消
```

| 状态 | 值 | 说明 |
|---|---|---|
| 待执行 | `pending` | 已受理，等待执行 |
| 执行中 | `running` | 流程执行中 |
| 大模型完成 | `llm_done` | 辅助分析完成，**尚未定级** |
| 规则定级完成 | `rule_done` | 规则引擎已定级 |
| 审查完成 | `completed` | 全流程结束 |
| 阻塞 | `blocked` | 被规则引擎判定阻塞 |
| 失败 | `failed` | 执行失败 |
| 已取消 | `cancelled` | 人工取消 |

**需求约束**：
- 阻塞状态**只能由规则引擎**依据风险等级判定后写入
- 阻塞任务经人工处理后回到**原阶段**继续，不从头重跑
- 状态机不得出现"无声卡死"——任何停滞都有明确状态与原因

### 5.2 回写状态（4 态）

未回写 → 回写中 → 成功 / 失败

## 六、非功能需求

### 6.1 安全需求（NFR-SEC）

| 编号 | 需求 | 判定标准 |
|---|---|---|
| NFR-SEC-01 | 所有业务接口默认需要鉴权 | 白名单外的路径一律要求有效凭证 |
| NFR-SEC-02 | 服务端强制权限校验 | 不依赖调用方自觉传参 |
| NFR-SEC-03 | 密码使用强哈希存储 | 数据库中非哈希格式的密码必须被拒绝入库 |
| NFR-SEC-04 | 模型服务全部本地部署 | **禁止调用公网 API**，合同原文属敏感数据 |
| NFR-SEC-05 | 前端开发服务器只监听本地回环 | 禁止绑定 `0.0.0.0` |
| NFR-SEC-06 | 敏感信息脱敏 | 配置自检、日志、错误信息中不得出现密钥明文 |
| NFR-SEC-07 | 越权行为可审计 | 所有越权尝试留痕 |

### 6.2 可审计性需求（NFR-AUDIT）

| 编号 | 需求 | 判定标准 |
|---|---|---|
| NFR-AUDIT-01 | 结论防篡改 | 结论内容生成哈希，任何改动可被发现 |
| NFR-AUDIT-02 | 判定可溯源 | 每条风险项可追到具体规则编码 |
| NFR-AUDIT-03 | 全链路留痕 | 任务的每一步操作可查询 |
| NFR-AUDIT-04 | 规则命中单独留日志 | 规则命中记录独立存储，供事后核查 |

### 6.3 可用性与容错（NFR-AVAIL）

| 编号 | 需求 | 判定标准 |
|---|---|---|
| NFR-AVAIL-01 | 大模型不可用不阻塞核心审查 | 模型服务离线时，规则引擎仍能完成定级与结论 |
| NFR-AVAIL-02 | 依赖不可用有明确提示 | 不伪装成"无风险"或"空结果" |
| NFR-AVAIL-03 | 解析未就绪显式报错 | 不得静默返回假成功 |
| NFR-AVAIL-04 | 健康检查分两级 | 存活探针不触碰外部依赖；就绪探针并发检查全部依赖 |

### 6.4 界面需求（NFR-UI）

| 编号 | 需求 | 判定标准 |
|---|---|---|
| NFR-UI-01 | 界面不得出现任何审批动作入口 | 底栏只有"写评论"，无审批通过/驳回等按钮 |
| NFR-UI-02 | 禁止编造展示数据 | 后端没有的字段显示为占位符，金额显示 0，不得填充假数据 |
| NFR-UI-03 | 必须展示权责声明 | 界面常驻"规则引擎终裁·大模型仅辅助"提示 |
| NFR-UI-04 | 空态必须有引导 | 无数据时给出说明与下一步入口，不留白屏 |
| NFR-UI-05 | 风险等级配色符合境内惯例 | 高风险用红色系，低风险用绿色系 |
| NFR-UI-06 | 大模型参考项不得显示为定级结论 | 参考项需明确标注来源 |

### 6.5 工程质量需求（NFR-ENG）

| 编号 | 需求 | 判定标准 |
|---|---|---|
| NFR-ENG-01 | 代码文件首行标注完整绝对路径 | 全部源文件无缺失 |
| NFR-ENG-02 | 核心逻辑有详细中文注释 | 覆盖逻辑、参数、流程、返回值 |
| NFR-ENG-03 | 禁止占位代码 | 不得出现"待实现""略""自行扩展" |
| NFR-ENG-04 | 遵守分层调用规则 | 见 SPEC.md 第三章 |
| NFR-ENG-05 | 禁止硬编码 | 连接串、密钥、端口、阈值一律走配置中心 |
