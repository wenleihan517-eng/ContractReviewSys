# 合同审批智能审查系统 — 交互与视觉设计说明书（UX/UI）

> **文档版本**：v1.0
> **文档性质**：交互逻辑与视觉规范。本文件描述"界面长什么样、用户怎么操作、状态如何反馈"。
> **配套文档**：[PRD.md](PRD.md) 产品需求｜[SPEC.md](SPEC.md) 技术规格｜[RUNBOOK.md](RUNBOOK.md) 运行说明
>
> **设计原则**：简洁企业风格。以 Ant Design 5 组件为基座，不引入第三方视觉体系。
> 界面的第一职责是**准确传达审查结论**，不是好看。

---

## 一、设计原则

### 1.1 四条基本准则

| 准则 | 含义 | 具体表现 |
|---|---|---|
| **结论优先** | 用户打开页面最先要看到的是"这份合同有没有问题、有多严重" | 统计卡在最上、等级标签用强色、风险列表可排序 |
| **来源透明** | 每个结论都要能看出是规则判定还是模型参考 | 规则命中与模型参考用不同视觉标记，参考项不得显示定级样式 |
| **状态明确** | 任何等待、失败、阻塞都有明确反馈，不留白屏 | 加载态有占位、空态有引导、错误态有原因与下一步 |
| **权责可见** | 系统是辅助而非决策者，这一点要在界面上常驻 | 顶栏常驻"规则引擎终裁·大模型仅辅助"声明 |

### 1.2 界面禁令（硬约束）

> 以下四条为**界面红线**，任何页面设计不得违反。

| # | 禁令 | 原因 |
|---|---|---|
| B1 | **不得出现任何审批动作入口** | 系统只写评论，不做审批决策。审批通过/驳回/转办/撤回/签章等按钮一律不得出现 |
| B2 | **不得编造展示数据** | 后端没有的字段显示为占位符（`—`）、金额显示 `0`，不得填充假数据充门面 |
| B3 | **模型参考项不得显示为定级结论** | 参考项必须明确标注来源，不得使用规则命中的定级样式 |
| B4 | **不得出现无引导的空白页** | 空态必须给出说明与下一步操作入口 |

## 二、信息架构

### 2.1 页面清单

| 页面 | 路径 | 访问角色 | 核心任务 |
|---|---|---|---|
| 登录页 | `/login` | 任意（已登录则送回首页） | 身份认证 |
| 合同审查大盘 | `/dashboard` | 全部三种角色 | 总览待审合同、批量调度、处理阻塞 |
| 智能审查工作台 | `/workbench/:taskNo` | 法务审查人、系统管理员 | 条款级风险复核、意见回写 |
| 合规规则与模板 | `/rules` | 仅系统管理员 | 维护审查规则与示范条款库 |

### 2.2 角色与首页对应

| 角色 | 登录后落点 | 可见导航项 |
|---|---|---|
| 业务经办人 | 合同审查大盘 | 合同审查大盘（1 项） |
| 法务审查人 | 智能审查工作台 | 合同审查大盘、智能审查工作台（2 项） |
| 系统管理员 | 合规规则与模板 | 全部三项 |

> **说明**：管理员登录后直接进入规则页而非大盘，因为规则维护是其首要职责。
> 大盘仍可访问。

### 2.3 导航结构

```
┌──────────────────┐
│  合同智能审查      │  ← 品牌区（侧边栏顶部）
├──────────────────┤
│  合同审查大盘      │  ← 三种角色均可见
│  智能审查工作台    │  ← 法务 / 管理员
│  合规规则与模板    │  ← 仅管理员
└──────────────────┘
```

**菜单可见性规则**：菜单按角色过滤，且与路由守卫**共用同一份权限配置**。
这保证不会出现"菜单里看得见、点进去被弹走"或"能进但菜单没高亮"的矛盾状态。

| 区域 | 规格 |
|---|---|
| 侧边栏宽度 | 224px，深色主题 |
| 顶栏高度 | 默认高度，左右内边距 24px |

### 3.3 顶栏元素

| 位置 | 元素 | 说明 |
|---|---|---|
| 左侧 | 系统名称 | 当前页面标题或系统名 |
| 右侧（前） | 权责声明标签 | 常驻，蓝色标签，文案"规则引擎终裁·大模型仅辅助" |
| 右侧（后） | 用户信息下拉 | 头像 + 显示名 + 角色标签，点击展开菜单 |

**用户下拉菜单**：

```
┌─────────────────────┐
│ 张三                │
│ [法务审查人]        │   ← 角色标签，按角色配色
├─────────────────────┤
│ 退出登录            │
└─────────────────────┘
```

**角色标签配色**：

| 角色 | 颜色 |
|---|---|
| 业务经办人 | 蓝 |
| 法务审查人 | 绿 |
| 系统管理员 | 金 |

> **显示名规范**：展示名（`display_name`）**只写姓名**，不得附加角色文字。
> 角色已由右侧标签表达，若显示名里再写一遍（如"张经办（业务经办人）"），
> 界面上会出现角色文案重复。
>
> **头像配色**：顶栏头像的渐变底色同样按角色取色（与标签同色系），
> 使"这个人是什么角色"在不读文字时也能一眼识别。具体色值见 §6.1。

**退出登录流程**：点击 → 二次确认弹窗 → 确认后清除本地凭证 → 跳登录页。
二次确认是必要的，避免误触丢失未保存的批注。

#### 表单字段

| 字段 | 类型 | 校验 | 图标 |
|---|---|---|---|
| 账号 | 文本输入 | 必填，非空校验 | 用户图标 |
| 密码 | 密码输入 | 必填，非空校验 | 锁图标 |
| 验证码 | 文本输入 | 必填，非空校验，**忽略大小写** | — |

#### 验证码设计

| 项 | 规格 |
|---|---|
| 类型 | 图形验证码（画布绘制） |
| 长度 | 4 位 |
| 尺寸 | 108 × 38 px |
| 字符集 | **剔除易混淆字符** 0 / O / 1 / I / l |
| 干扰元素 | 3 条干扰线 + 逐字符随机旋转（±0.4 弧度）+ 24 个干扰点 |
| 刷新方式 | 点击图形刷新 |

**刷新联动**：刷新验证码时**必须同时清空验证码输入框**。
否则用户看到的图已换、输入框还留着旧值，提交必然失败。

#### 交互流程

```
用户进入 /login
      ↓
[已登录？] ──是──→ 跳转到该角色首页
      ↓否
渲染登录表单（生成首张验证码）
      ↓
用户填写三项 → 点击"登录"
      ↓
[表单校验通过？] ──否──→ 字段级错误提示
      ↓是
[验证码匹配？] ──否──→ 提示"验证码错误" + 刷新验证码 + 清空输入
      ↓是
调用登录接口
      ↓
[成功？] ──否──→ 按错误类型提示（见下表）
      ↓是
保存凭证 + 用户信息 → 记住账号名 → 延迟 320ms → 跳转
      ↓
[地址栏带 from 参数？] ──是且安全──→ 回到原页面
      ↓否
跳转到该角色首页
```

#### 错误提示映射

| 后端错误 | 提示文案 | 处理 |
|---|---|---|
| 账号或密码错误 | 使用后端返回文案 | 刷新验证码 |
| 账号已停用 | 账号已停用，请联系管理员 | — |
| 账号已锁定 | 账号已锁定，请稍后再试 | — |
| 参数校验失败 | 参数校验失败提示 | — |
| 网络异常 | 网络异常，请检查网络连接 | — |
| 其他 | 登录失败，请稍后重试 | — |

#### 安全交互要求

| 要求 | 实现 |
|---|---|
| 账号可记住 | 仅将**账号名**存入本地存储 |
| 密码绝不落盘 | 密码只存在于表单与请求体，不写入任何本地存储 |
| 开放重定向防御 | 回跳地址必须以内斜杠开头且不以双斜杠开头，否则忽略并使用角色首页 |
| 验证码防猜测 | 提交前本地比对，错误即刷新 |

| 控件 | 行为 |

| 操作 | 前置条件 | 确认 |

| 上传合同送审 | — | 打开上传弹窗 |

#### 上传弹窗（三步串行）

```
步骤 1：选择文件
    ↓
步骤 2：填写元数据（合同名称 / 合同类型 / 相对方 / 金额）

步骤 3：确认并提交
```

**设计要点**：三步串行而非一屏堆砌，避免用户漏填关键元数据——
元数据直接影响路由决策（金额决定是否走深度复核）。

#### 空态

无任务时不留白屏，展示：
- 说明文案"暂无审查任务"
- 上传合同入口按钮

```

│              [图标]                     │
│                                         │
│        请先选择要审查的合同              │
│                                         │
```

#### 双栏比例与滚动

| 栏位 | 宽度占比 | 滚动 |
|---|---|---|
| 合同原文 | 58% | 内部独立滚动 |
| 风险列表 | 42% | 内部独立滚动 |

两栏独立滚动，互不影响定位。

#### 原文高亮与定位

**这是工作台的核心交互。**

| 行为 | 效果 |
|---|---|
| 风险项在原文中的位置 | 用等级对应的颜色背景高亮 |
| 点击右侧风险卡片 | 原文自动滚动到对应位置并强调 |
| 点击原文中的高亮 | 右侧对应风险卡片滚动到可见区 |
| 无位置信息的风险 | 显示「全文」标记，不参与定位跳转 |

**区间切分铁律**（技术约束，直接影响正确性）：

| # | 规则 |
|---|---|
| 1 | 文本块位置与风险位置使用**同一坐标系**，区间为**左闭右开** |
| 2 | 按风险区间切分原文后，**拼接结果必须严格等于原文**（零丢失、零重复） |
| 3 | **重叠的风险区间必须先合并**，否则会出现文字重复渲染 |
| 4 | 跨页风险需正确换算为页内偏移 |
| 5 | 起止位置均为 0 视为"无位置信息"，显示「全文」，**禁止编造页码** |

#### 风险卡片

**卡片必含四要素**：

| 要素 | 说明 |
|---|---|
| 等级标签 | 规则命中的风险显示等级（强色）；参考项**不显示等级** |
| 依据 | 命中依据，含原文摘录与规则说明 |
| 原文 | 对应的合同原文片段 |
| 建议 | 修改建议 |

**两种来源的视觉区分**（关键）：

| 来源 | 标记 | 等级标签 | 说明 |
|---|---|---|---|
| 规则命中 | 明显的"规则命中"标记 | 显示 | 参与定级，决定阻塞 |
| 大模型参考 | 明显的"参考"标记 | **不显示** | 仅供参考，不影响结论 |

**排序规则**：规则命中优先，其次按风险等级排序。
这保证用户先看到真正决定结论的项。

## 五、状态反馈规范

### 5.1 四种基本状态

| 状态 | 表现 | 禁止 |
|---|---|---|
| **加载中** | 骨架屏或加载指示器 + 文案 | 不得白屏 |
| **空数据** | 图标 + 说明文案 + 下一步入口 | 不得留白屏或无引导 |
| **错误** | 明确错误原因 + 可执行的下一步 | 不得只显示"出错了" |
| **部分可用** | 明确标注哪部分不可用及其影响 | 不得伪装成完整数据 |

### 5.2 关键场景的状态要求

| 场景 | 要求 |
|---|---|
| 后端不可用 | 页面顶部显示提示，说明影响范围，不编造数据 |
| 大模型服务不可用 | **不视为错误**——大模型是辅助，规则引擎仍可完成审查，界面正常展示结果 |
| 任务阻塞 | 明确显示阻塞原因（中文说明，不只显示英文码）+ 处理入口 |
| 回写失败 | 明确标注失败状态，提供重试入口，不静默丢失 |
| 审查进行中 | 显示进度，不显示不完整的风险列表误导用户 |

### 5.3 阻塞原因文案

| 原因码 | 界面文案 |
|---|---|
| `DOC_ENCRYPTED` | 文档已加密，无法解析。请上传未加密的合同文件 |
| `SCAN_TOO_BLURRY` | 扫描件过于模糊，无法识别文字。请重新扫描或提供更清晰的版本 |
| `EMPTY_CONTENT` | 合同正文内容为空或过短。请确认文件内容完整 |
| `PARSE_FAILED` | 文档解析失败。请确认文件格式正确或联系管理员 |
| `RETRY_EXHAUSTED` | 多次重试后仍失败。请联系管理员人工处理 |
| `MANUAL` | 已被管理员人工置为阻塞 |

## 九、可访问性与文案规范

### 9.1 文案规范

| 规则 | 说明 |
|---|---|
| 用词准确 | 使用"审查""风险项""审批回写"等业务术语，不用"检测""异常"等泛化词 |
| 不承诺 | 不说"保证无风险"，说"未发现符合规则的风险" |
| 有出处 | 涉及判定的文案标注来源 |
| 可执行 | 错误提示给出下一步动作，不只描述问题 |
| 状态用词一致 | 状态名称与后端枚举的中文映射完全一致，不另造词 |

### 9.2 可访问性

| 项 | 做法 |
|---|---|
| 颜色不是唯一信息载体 | 风险等级除颜色外同时有文字标签 |
| 交互元素可聚焦 | 使用组件库默认的键盘导航能力 |
| 图标有文字说明 | 纯图标操作提供悬浮提示 |
| 对比度 | 采用组件库默认配色，保证正文可读性 |
