# 演示样本说明（含脱敏声明）

## 一、脱敏声明

本目录下所有样本均为**虚构数据**，用于功能演示与验收，不含任何真实主体信息。

| 数据项 | 处理方式 | 示例值 |
|---|---|---|
| 企业名称 | 虚构为"甲方甲科技有限公司""乙方乙软件有限公司"等 | 甲方丙制造有限公司 |
| 统一社会信用代码 | 使用明显虚构的占位码 | `91110000MA0000000X` |
| 法定代表人 / 联系人 | 以"甲某""乙某联系人"代替 | 丙某 |
| 详细地址 | 保留行政区划（保证业务合理性），门牌全部虚构 | 北京市海淀区示例路 1 号 |
| 联系电话 | 区号保留，号码置零 | `010-0000XXXX` |
| 银行账号 / 开户行 | 全部置零 / 用"示例银行示例支行" | `0000 0000 0000 0000 000` |
| 合同编号 | 前缀改为 `DEMO-` | `DEMO-CG-2026-0918` |
| 产品型号 | 前缀改为 `DEMO-` | `DEMO-PT-8800` |

**保留未脱敏的地方有意为之**：行政区划、金额、日期、条款正文。
金额与日期是规则引擎的计算输入（如大额合同阈值判定、逾期天数计算），
行政区划用于保证"签订地点"字段的业务合理性，这些都不构成主体识别信息。

## 三、脱敏安全边界（改样本前必读）

样本正文中**以下内容一旦改动，规则命中会静默失效**——系统不会报错，
只会在演示时表现为"该命中的风险没命中"。

### 分类器依赖的条款标题关键词

条款类型由标题优先判定，因此**条款标题中的这些词不能动**：

| 条款类型 | 必须保留的关键词 |
|---|---|
| `payment` | 付款、货款、价款、支付、结算、发票 |
| `delivery` | 交付、交货、验收、运输、发货 |
| `warranty` | 质量、保证、保修、质保、瑕疵 |
| `liability` | 违约、赔偿、损失、责任、罚款 |
| `confidentiality` | 保密、商业秘密、信息披露 |
| `ip` | 知识产权、专利、著作权、商标、成果归属 |
| `dispute` | 争议、仲裁、诉讼、管辖、协商 |
| `subject_matter` | 标的、金额、合同价、总价 |
| `party_info` | 甲方、乙方、当事人、法定代表人 |

### 规则匹配依赖的原文措辞（精确串匹配）

| 规则 | 必须原文保留的措辞 |
|---|---|
| `PAY-001` | `签订后即支付全部` |
| `BAL-004` | `乙方承担全部赔偿责任` |
| `PUR-001` | 依赖"缺失 `delivery` 条款"→ 故**第四条标题不能出现"交付/验收"** |
| `PUR-002` | 依赖"缺失 `warranty` 条款"→ 故**标题不能出现"质量/保证"**（正文出现"保证"会误分类） |
| `NUM-004` | 依赖 `contract_amount ≥ 5000000` → 销售合同金额**不能低于 500 万** |
| `IP-001` | 正则需 `知识产权…侵权…全部/一切…责任/损失…由/均由…乙方` |

### 已验证的命中结果（脱敏后实测）

```
样本1 purchase / 86万
  条款数 8 | 命中 5 | critical | blocked=True
  ['PAY-001', 'PUR-001', 'PUR-002', 'BAL-004', 'IP-001']
  {'low': 0, 'medium': 0, 'high': 2, 'critical': 3}

样本2 sales / 1200万
  条款数 10 | 命中 2 | high | blocked=True
  ['BAL-004', 'NUM-004']
  {'low': 1, 'medium': 0, 'high': 1, 'critical': 0}
```

改动样本后请重跑上述校验，确认命中集合与上表一致。

> **复验说明（2026-09-21）**：上表结果最初由"直接调用规则引擎"的隔离测试得出
> （手工传入 `contract_type`），**未覆盖真实 HTTP 链路**。复验发现该缺口，
> 已修复并在**端到端链路**（上传 → 建任务 → 触发解析 → 自动审查 → 取结论）
> 上重新实测：样本1 命中 `['PAY-001','PUR-001','PUR-002','BAL-004','IP-001']`
> / `critical` / `blocked`，样本2 命中 `['BAL-004','NUM-004']` / `high` / `blocked`，
> 与上表逐字段一致。当模拟审批服务在运行时，其自动创建的占位审批单
> **不会**再提供 `contract_amount` / `contract_type` / `counterparty`，
> 以免静默顶掉从合同原文识别出的真实值（详见
> `docs/REQUIREMENT_2.4_AUDIT.md` §九）。

## 四、重新生成异常样本

```bash
cd docs/demo_samples
python gen_exception_samples.py
```

依赖：`pypdf`（生成加密 / 空白 PDF）、`Pillow`（生成模糊扫描件）。
缺少依赖时脚本会明确报错，不会静默跳过。

生成后可用以下方式自测触发条件：

```python
import pypdf
print(pypdf.PdfReader('exception1_加密合同.pdf').is_encrypted)   # True
print(len(pypdf.PdfReader('exception3_空白合同.pdf').pages[0].extract_text().strip()))  # 0，阈值 50
```

模糊扫描件的判据是 OCR 平均置信度 < 0.6；样本通过
"低分辨率放大 + 高斯模糊 r=8 + JPEG q=12" 三重劣化保证必然低于阈值。
