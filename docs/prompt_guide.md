# 合同审批智能审查系统 — 常见问题修正话术

> **文件路径**：`docs/prompt_guide.md`
>
> **用途**：本文件汇总系统实现过程中反复出现的典型问题，并为每一条给出**标准修正话术**。
> 话术可直接用于需求澄清、开发交底、代码评审提问与验收核对。
>
> **性质说明**：本文件中的条目是**验收基线与检查准则**，不是缺陷记录。
> 每条话术描述的是"应当如何实现"的判定标准，用于核对当前实现是否达标；
> 而不是"曾经出现某个 Bug"的修复日志。
> 因此条目内容保持原始表述不做改写，仅在其下补充验收核对指引。

---

## 一、使用方式

1. **需求阶段**：把对应条目的话术原文发给开发方，作为需求约束。
2. **开发阶段**：开发自检时逐条核对"验收核对点"列出的具体机制是否落地。
3. **验收阶段**：以"验收核对点"为检查清单，逐项确认或标记未达标。
4. **评审阶段**：以话术原文作为提问依据，要求开发方给出代码级证据（文件 + 行号 + 实测结果）。

**判定原则**：话术要求的能力必须有**代码级实现 + 可复现的实测证据**，
口头承诺、截图说明、后续补做均不视为达标。

## 四、更新【常见问题修正话术】新增一条

【角色路由权限错误】
请严格实现前后端双重权限校验，登录成功后依据角色自动跳转对应页面；禁止前端仅做页面隐藏，后端接口必须校验角色权限，防止越权调用接口，修正权限逻辑。

**验收核对点**（检查准则，非修复记录）：

| # | 核对项 | 达标判据 |
|---|---|---|
| 1 | 登录成功后依据角色自动跳转对应页面 | 三种角色各自的登录落点正确：业务经办人 → 合同审查大盘页；法务审查人 → 智能审查工作台；系统管理员 → 合规规则与模板管理页。跳转由角色决定，不由用户手选 |
| 2 | 前后端**双重**权限校验 | 前端负责体验（拦截与引导），后端负责安全（强制判定）。两层都必须存在，缺一不可 —— 只有前端或只有后端均判不达标 |
| 3 | 禁止前端仅做页面隐藏 | 前端菜单/按钮的显隐只能作为体验优化，**不得作为权限边界**。判据：直接手敲受限页面 URL，仍必须被拦回，不能仅靠"菜单里看不见" |
| 4 | 后端接口必须校验角色权限 | 每个受保护接口都绑定明确的角色/权限要求，并在服务端强制校验。未授权主体调用受限接口必须被拒绝，且返回明确的拒绝语义 |
| 5 | 防止越权调用接口 | 覆盖三类越权：横向（同角色访问他人数据）、纵向（低权限角色调用高权限接口）、路径绕过（通过路径变体规避前缀匹配）。三类均须被拦截 |
| 6 | 越权行为可追溯 | 越权请求被拒绝时须留下审计痕迹，可事后追溯"谁在何时尝试访问了什么" |
| 7 | 越权后的用户体验 | 已登录用户访问无权页面时，不得白屏或报错，应自动跳转到其角色首页并给出无权限提示 |
| 8 | 权限定义**唯一权威源** | 角色与权限点的定义必须集中在一处，前后端引用同一份语义，不得在两处各写一套导致口径漂移 |
| 9 | 权限校验不可被绕过 | 校验必须发生在服务端的统一入口，不得依赖调用方自觉传参；非法输入不得导致校验被跳过 |
